# Windows Support Audit

Last audited: 2026-08-29.

Quarterdeck's Windows code-remediation backlog is complete. Support remains experimental because this audit was implemented and locally validated from macOS: the required native workflow and the real-provider manual matrix still need to pass for the committed tree. The release ledger is [`windows-compatibility-todo.md`](./windows-compatibility-todo.md), and reproducible commands plus acceptance details are in [`windows-native-smoke.md`](./windows-native-smoke.md).

## Scope and method

Two complete passes covered dependency installation, build/package scripts, CLI startup and shutdown, environment lookup, executable discovery, shell and host launch, supported-agent adapters, PTY/session lifecycle, terminal restore, startup recovery, process ownership, diagnostics, state persistence, file reads/writes/deletion/locking, worktrees, Git parsing and mutations, server/browser path identity, Agent Lab, unit/integration fixtures, and GitHub Actions. The second pass specifically searched for POSIX-only fixtures, case-sensitive environment assumptions, shell parsing, privileged symlink requirements, path-length and reserved-name failures, line-ending policy, and Windows cleanup races.

## Current assessment

- **Install, build, and packaging:** Root and web lockfiles carry the toolchain's Windows-native optional packages. Build, clean, bootstrap, link, dev, dogfood, Playwright, and Agent Lab launchers use Node filesystem/process APIs and run npm's absolute JavaScript entrypoint through the absolute Node executable; executable chmod is POSIX-only. Agent Lab derives Git's shared metadata directory from bounded `.git`/`commondir` pointers instead of launching bare Git from the checkout. The required job installs from clean lockfiles, builds, starts the packaged CLI, fetches the bundled HTML shell, and shuts it down through the production parent-disconnect path.
- **Environment and command discovery:** Windows environment lookup and merges are case-insensitive, so duplicate-cased `PATH`, `ComSpec`, `SystemRoot`, HOME/profile, Git, and provider variables do not select stale values. Command discovery recognizes explicit `.cmd`, `.bat`, `.com`, `.exe`, and `.ps1` targets, searches Windows extensions without assuming an extensionless executable, and returns the exact inherited-`PATH` file used by launch owners.
- **Paths and names:** Runtime and browser identity comparisons normalize separators and case only where Windows semantics require it while preserving repository paths for display and Git, including valid POSIX leading/trailing whitespace. Project indexes, task/worktree identity, metadata/query reconciliation, path display, file mutation, drive-root worktree labels, and injected-platform tests share that contract. User/provider-derived names reject device names, alternate data streams, invalid/control characters, trailing dots/spaces, and unsafe post-truncation results.
- **Shell and process launch:** Interactive Windows shell terminals use trusted `ComSpec`. Normal launches resolve their exact executable before entering the project cwd and prefer direct argv execution; command shims use the shared `cmd.exe /d /v:off /s /c` adapter with the exact shim path, while fixed hook/status-line and `.ps1` shim paths use absolute system PowerShell. Timeouts terminate the process tree. Project shortcuts retain their explicit shell contract, while folder, file, URL, and IDE launch use the server-owned host-integration boundary and trusted executable/argv pairs.
- **Hooks and status line:** Claude hooks, Codex hooks, and Claude's optional status line use one command serializer. On Windows, absolute system PowerShell runs a fixed encoded bootstrap that starts the exact Quarterdeck executable with standard Win32 argv serialization and inherited stdio. Native coverage proves working-directory and `PATH` decoys cannot intercept it and that spaces, multiline values, shell metacharacters, stdin, and stdout survive exactly.
- **PTY and terminal restore:** Task and shell sessions use `node-pty`/ConPTY. A Windows task launch waits for a real PTY PID before durable ownership registration and runtime handoff. Forced same-size redraw uses a bounded one-row ConPTY resize and immediately restores the requested geometry instead of attempting Unix `SIGWINCH`. The native deterministic scenario covers task and shell PTYs, CR input, provider transition, forced resize, control/IO disconnect and reconnect, authoritative restore, exact geometry, and clean stop. Real provider TUI behavior remains an acceptance item, not an unimplemented code path.
- **Process ownership and shutdown:** Windows cleanup is authorized only by protected launch records containing exact runtime/root PID and CIM creation identities after registration proves the root remains that runtime's direct child. Startup skips live owners, prunes malformed/missing/reused identities, rechecks an abandoned root immediately before signalling, and calls absolute System32 `taskkill.exe`; shutdown concurrently reclaims only the current runtime's exact registered roots. Parent disconnect enters the runtime shutdown controller directly, and wrappers propagate it through stdin with Windows-specific cleanup budgets and bounded force-kill fallback.
- **Filesystem and worktrees:** Ignored directories use junctions without requiring Developer Mode. Ignored files prefer symlinks and fall back to exclusive task-local copies when Windows denies link creation; copy/junction failures are typed and fail preparation. Recursive removal retries transient sharing violations, atomic writes avoid POSIX-only mode assumptions, and lock cleanup preserves ownership. Workdir and provider-history reads combine lexical/canonical containment, no-follow where available, pre/post-open canonical and file-identity checks, bounded handle reads, and rejection of a replaced canonical parent.
- **Git:** Commands resolve the exact inherited-`PATH` Git executable before setting a repository cwd, use argv execution, and enable `core.longpaths=true` on Windows. Path-bearing status, diff, conflict, and file-list protocols use NUL delimiters; leading whitespace is preserved; case-only rename is explicit; and test repositories disable host `core.autocrlf` so byte-level assertions are deterministic. Native smoke creates, commits, checks out, and reads a path longer than 260 characters while invalid project-local `git.exe`, `codex.exe`, and `code.exe` decoys prove current-directory search cannot intercept runtime work.
- **Diagnostics and privacy:** Runtime descriptors/tokens, journals, bundles, Agent Lab artifacts/state, staged credentials, and browser state are created below a protected current-user + LocalSystem DACL before content is written, including configured state homes and custom export roots. Failure stays memory-only or fails an explicit operation closed. Redaction recognizes Windows paths with spaces, and generated evidence filenames are Windows-safe.
- **Browser/UI state:** Windows path aliases compare as one identity across board synchronization, task state, metadata stores, query equality, and file-tree presentation. Display helpers accept either separator without rewriting source data or collapsing distinct non-Windows paths.
- **Tests and CI:** Platform-neutral tests cover simulated Windows branches and use Windows-native fixtures when executed on Windows: `.cmd` commands, directory junctions rather than privileged file symlinks, platform-aware path expectations, guarded POSIX permission assertions, case-aware environments, long paths, and stable LF Git data. A non-optional `windows-latest` job adds the native ConPTY, DACL, exact process-ownership, packaged CLI, host-launch, worktree, path-fidelity, and shutdown scenarios before web tests.

## Remaining acceptance, not remediation

- Observe the required `Windows native` job on the exact committed branch revision. This local macOS worktree cannot execute ConPTY, Windows command shims, CIM, DACL, or `taskkill.exe` natively.
- Run authenticated Claude Code, Codex, and pinned Pi on a normal non-administrator Windows account through the manual lifecycle matrix, actual IDE/folder launch, crash recovery, and cross-account diagnostic access check.

Any failure in those gates becomes a new concrete remediation with an automated regression. Until both pass, keep the README's experimental label.
