## 2026-08-31 — Enforce the full runtime suite on native Windows

The first required Windows CI rerun reached the full runtime suite and exposed 37 failures across 20 files that POSIX-only validation had hidden. Most were stale fixtures: Git repositories inherited checkout line-ending conversion, fake agents supplied only batch shims even when multiline-safe PowerShell launch was required, mocks asserted bare executable names after production began retaining exact inherited-`PATH` targets, and tests expected POSIX path spellings or decoded hook payloads on Windows. Two production boundaries also needed correction: workdir traversal must be classified before Windows filename rules, and protected diagnostic/Agent Lab/managed-process storage must apply its exact current-user-and-LocalSystem DACL through an encoded PowerShell command. The ACL script retains owner/group metadata, removes inherited and explicit access rules through SID-based inbox .NET Framework APIs, and then adds only the current user and LocalSystem, avoiding account-name translation and PowerShell module autoloading; its Windows PowerShell JSON input is enumerated and explicitly converted to scalar strings before filesystem calls. Its failure surface is limited to a bounded operation-stage/exception-type/error-ID classifier rather than command output or affected paths. Agent Lab normalizes real-provider configuration paths at the environment boundary, the native command probe models `cmd.exe`'s already-serialized argument boundary and accepts only PowerShell's exact first-use progress CLIXML envelope as non-command stderr, and hook timing fixtures explicitly order provider progress after submitted input. Batch command serialization follows the established single escape pass for ordinary `.cmd`/`.bat` files and reserves double escaping for `node_modules/.bin` proxy shims; the native proxy fixture uses that owned path shape. Arguments containing quotes, line breaks, or trailing backslashes fail closed without a sibling PowerShell shim because cmd cannot transport them unambiguously. Integration cleanup now requests confirmed task exit before removing its Windows project checkout. Notable files: `src/core/private-directory.ts`, `src/core/windows-cmd-launch.ts`, `src/workdir/workdir-path-policy.ts`, Windows Agent Lab/config/Git fixtures, and the required native smoke. ## 2026-08-29 — Fence Windows process cleanup with durable launch identity

Windows orphan cleanup previously enumerated every process and selected parentless or PID-reused-parent rows by Claude/Codex/Pi executable names or hosted `node.exe`/`cmd.exe` command lines. That could target an unrelated user's agent and still could not prove a candidate belonged to Quarterdeck. Each managed Windows task PTY now writes one exclusive record beneath a protected state-home registry before launch handoff. The record contains no command or path data—only its launch ID and the CIM creation identities of the owning Quarterdeck runtime and PTY root, captured only when CIM still reports the root as that runtime's direct child. A clean PTY exit retires it. Startup skips any exact live owner, prunes malformed, missing, or PID-reused roots without signalling, and returns only exact roots whose owner disappeared; shutdown may additionally include the current runtime. Cleanup rechecks root creation evidence immediately before signalling. Identity/ACL/query/parentage failure is fail-closed: a new PTY is stopped rather than exposed untracked, and startup recovery cannot proceed past unverifiable cleanup.

The protected-directory primitive now serves both diagnostic confidentiality and registry integrity. Windows process snapshots use the absolute system PowerShell executable and fixed encoded code, while tree termination replaced the shell-based third-party helper with argv-only `execFile` of absolute System32 `taskkill.exe`. Portable tests cover registry persistence, live and reused owners/roots, malformed content, revalidation, unrelated name/command inventory, registration failure, and PTY retirement. ## 2026-08-28 — Preserve Windows hook and status-line argv through one command owner

Claude and Codex require hook and status-line configuration as shell strings. Quarterdeck previously built those strings by wrapping each Windows token in double quotes and doubling embedded quotes. That did not protect `%NAME%`, delayed `!` expansion, carets, pipes, ampersands, or grouping characters from `cmd.exe`, so an otherwise valid install path or argument could be expanded, split, or rewritten before Node received it.

`buildShellCommandLine(...)` now owns the platform contract, and `buildQuarterdeckCommandLine(...)` combines it with exact runtime invocation resolution. On Windows the visible shell text invokes the absolute PowerShell executable beneath the validated system root and carries only an encoded bootstrap; the bootstrap uses `ProcessStartInfo` to start the resolved executable directly with a standard Win32 argv command line. This avoids both current-directory/`PATH` executable interception and interpreter expansion of invocation data, while unredirected `ProcessStartInfo` handles deliberately preserve hook/status-line stdin, stdout, and stderr. Claude hooks, Codex hooks, and the optional Claude status line all route through that seam. Portable tests cover system executable resolution, argv quoting, encoded payload isolation, runtime invocation resolution, and caller wiring. The required native smoke puts a copied `node.exe` at `powershell.exe` in the working directory and `PATH`, copies the real target beneath a path containing spaces, percent expansion syntax, delayed-expansion syntax, carets, ampersands, and parentheses, then executes the generated command through `cmd.exe` and verifies the decoy is bypassed and every required metacharacter plus stdin/stdout round-trips unchanged. Notable files: `src/core/{shell,quarterdeck-command,windows-cmd-launch}.ts`, `src/{claude-hooks,codex-hooks}.ts`, `src/commands/statusline.ts`, and the focused/native command tests. Commit: `4b53decf`.

## 2026-08-28 — Make ignored-file worktree setup deterministic on Windows

Eligible ignored setup files were linked with the same best-effort primitive as ignored directories. Windows directory junctions do not need Developer Mode, but file symlinks commonly require an unavailable privilege; the shared catch converted that denial—and every other link error—into a successful but incomplete worktree. The mirror owner now prefers the existing file symlink and, on Windows failure, creates an exclusive task-local copy. The exclusive copy cannot overwrite a racing target and, unlike a hard link, task writes cannot mutate the primary checkout. A copy is an initial setup snapshot: an existing task-owned target remains authoritative on later ensures.

If both file operations fail, or if a directory junction fails, `IgnoredPathMirrorError` identifies the source, target, and path kind with retry guidance. New-worktree preparation retains its fail-closed cleanup, while an existing worktree remains intact and reports the ensure failure. Portable unit coverage forces file fallback, copy failure, junction failure, and non-Windows behavior; filesystem integration covers ignored file/directory visibility and repeated ensure. The required native smoke adds a real ignored file beside the existing directory-junction assertion. ## 2026-08-28 — Make managed runtime shutdown Windows-safe

Windows does not deliver Node's programmatic `SIGTERM` to JavaScript listeners; it unconditionally terminates the target. Quarterdeck nevertheless used `process.kill(process.pid, "SIGTERM")` after a parent-pipe disconnect and forwarded the same signal from development, dogfood, and Agent Lab supervisors, bypassing the cleanup path those calls intended to trigger. The graceful-shutdown controller now exposes an idempotent programmatic request that invokes the existing runtime owner directly. A real signal racing that request is suppressed for the same bounded duplicate window, while a later signal retains force-exit behavior.

Managed runtime processes now receive a dedicated stdin pipe. Supervisors close it to request cleanup, and intermediate development wrappers propagate the disconnect down to the CLI instead of emulating a Windows signal. `dev-runtime` now keeps its simple source-watch policy outside the child-process owner and launches the TypeScript entrypoint directly, so a restart or parent shutdown can await the exact runtime instead of waiting for a persistent `tsx watch` intermediary's force-kill timeout. The integration server no longer injects an IPC hook that converted test shutdown into a synthetic `SIGINT`; it exercises the production parent-disconnect contract and verifies both direct and source-watching launches reach a diagnostic `stopped` state before process exit. Notable files: `src/core/graceful-shutdown.ts`, `src/cli.ts`, `scripts/dev-process.mjs`, `scripts/{dev-full,dev-runtime,dogfood}.mjs`, `scripts/agent-lab/supervisor.ts`, and focused lifecycle/integration tests. ## 2026-08-07 — Claude restore geometry and rendering investigation

Claude task terminals now use the same pre-restore forced geometry update as Codex. The resize message is sent before `request_restore`, and a same-size Unix resize still emits `SIGWINCH`, so Claude redraws against the attached browser dimensions before the server mirror snapshot is applied. Quarterdeck's injected Claude status line is now strictly opt-in: the global default is off, low-level launches require an explicit `true`, and Settings exposes the control under Harnesses.

The follow-up rendering investigation found that Claude's classic renderer and xterm scrollback have an unavoidable ownership conflict: preserving erase-cleared lines keeps native wheel history but records transient full-screen redraw frames, while suppressing those lines removes conversation history. Filtering the PTY byte stream would also risk dropping semantic output around chunk and resize boundaries. The recommended durable path is to dogfood Claude's alternate-screen fullscreen renderer, let Claude own its virtualized transcript, and keep xterm responsible for the live viewport and serialized restore state.
