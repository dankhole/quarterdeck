## 2026-08-25 — Transient agent availability and browser-launch observability

Dogfood diagnostics showed two interrupted Codex tasks fail startup recovery after one shared three-second availability probe, followed by a manual Restart that failed immediately even though Codex was installed and healthy. Node reports an `execFile` timeout with a null code plus a terminating signal; the registry treated that callback as a completed probe, converted its empty output to CLI unavailability, cached the transient negative, and later served it stale while refreshing. Task startup then discarded the availability reason behind a generic installation error. The in-memory cache reset on runtime restart, after which both tasks launched normally.

Availability now has typed durable and transient outcomes. Probe timeout or execution failure is never cached; display reads may retain an older value, but process launch reuses only a fresh successful result and awaits expired probes. Startup recovery retries one transient probe, while deterministic missing/version/feature failures remain bounded preparation failures. Structured diagnostics retain only agent ID, probe kind, duration, outcome, and availability classification. The browser symptom from the same report was not causally linked: existing browser connections could not prove an auto-open attempt, and the macOS wrapper previously resolved at process spawn without checking launcher exit. Startup auto-open now records requested/accepted/failed events and awaits `/usr/bin/open` directly, without depending on inherited `PATH` or waiting for the browser lifecycle. Notable files: `src/config/agent-registry.ts`, `src/server/task-session-start-service.ts`, `src/server/browser.ts`, `src/cli.ts`, and focused registry/browser/CLI tests. ## 2026-08-25 — Agent Lab detached-browser ownership backstop

Live process inspection found 12 Playwright daemon roots and their Chrome/Chromium descendants surviving completed Agent Lab runs for 42 minutes to nearly 22 hours. Browser action transcripts showed that repeated `open` calls replaced the registered named session, while detached daemons from prior opens remained alive; the final `close` could address only the newest registry entry. This matches Playwright's documented orphan-process failure mode, and the previous five-second Quarterdeck helper silently ignored every close or cleanup failure.

Agent Lab now snapshots the host process table before and after the normal Playwright close, resolves `playwright-core` from the installed CLI's own module context, identifies daemon roots only when the executable is Node and the first daemon argument is the exact `qd-<run-id>` session, then terminates the union of those roots and their captured descendants. Residual processes or an unverifiable cleanup mark the disposable run failed, but managed runtime/web shutdown and final evidence capture still complete. Pool-owned entry points now initialize on the first task-terminal container attach, direct acquire, or prewarm, preserving the existing four-slot roles, warmup/previous TTLs, restore behavior, staging, and rotation policy. Dedicated home/detail shell terminals continue through their separate registry and start shared DOM diagnostics without initializing the task-agent pool.

The invariant is that deferred construction changes only when pool resources are allocated, not terminal attachment or reuse semantics, and shell terminals must not become pooled task terminals as a side effect. ## 2026-08-11 — Runtime session delivery classification

Runtime session ingest remains immediate and the active project still receives every coalesced summary update, including activity text. The delivery layer now compares each summary with the last store snapshot and only updates cross-project notification memory when the shared semantic task indicator changes; it only rebuilds project-list counts when a session crosses the `awaiting_review` boundary that can reproject an in-progress card into Review. Activity, resume metadata, checkpoints, and other count-neutral changes therefore avoid global notification board reads and project scoreboard rebuilds without weakening approval, review, failure, or resume behavior. Runtime-state broadcasts also serialize one shared frame per project/global delivery while retaining per-client send failure isolation.

The invariant is that classification may skip dependent projections only when their observable semantic inputs are unchanged; it must never suppress the active project's authoritative session delta or infer lifecycle from PTY output. Notable files: `src/server/runtime-state-message-batcher.ts`, `src/server/runtime-state-client-registry.ts`, and focused runtime server tests. ## 2026-08-07 — Automatic title request coalescing

Automatic title generation is launched after browser-owned board saves whenever a card still has `title === null`. Consecutive saves could therefore start overlapping helper-LLM calls for the same card before the first title update returned. `createStateOps(...)` now owns a per-project/task in-flight set around automatic generation: overlapping saves skip the duplicate, the key clears in `finally` after success/fallback/failure, and later saves can retry. Manual regeneration remains independent because it is an explicit awaited action and may use richer session context.

The invariant is one active automatic title request per project/task without serializing unrelated cards or projects. Notable files: `src/trpc/project-api-state.ts` and `test/runtime/trpc/project-api-state.test.ts`. ## 2026-08-07 — Cached project sidebar pill ownership

Project sidebar task-count pills now derive from the board that is actually on screen, including a stale-while-revalidate board restored during a project switch. ## 2026-08-07 — Claude restore geometry and rendering investigation

Claude task terminals now use the same pre-restore forced geometry update as Codex. The resize message is sent before `request_restore`, and a same-size Unix resize still emits `SIGWINCH`, so Claude redraws against the attached browser dimensions before the server mirror snapshot is applied. Other agents and shell terminals keep the normal restore path. Quarterdeck's injected Claude status line is now strictly opt-in: the global default is off, low-level launches require an explicit `true`, and Settings exposes the control under Harnesses.

The follow-up rendering investigation found that Claude's classic renderer and xterm scrollback have an unavoidable ownership conflict: preserving erase-cleared lines keeps native wheel history but records transient full-screen redraw frames, while suppressing those lines removes conversation history. Filtering the PTY byte stream would also risk dropping semantic output around chunk and resize boundaries. The recommended durable path is to dogfood Claude's alternate-screen fullscreen renderer, let Claude own its virtualized transcript, and keep xterm responsible for the live viewport and serialized restore state. The staged design and rollback criteria are recorded in `docs/claude-terminal-rendering-plan.md`.
