Baseline: `fb9a34fbc41fb8464dd5133db066120c24eb866c`. This independently checks all six P1 findings: five application findings in M01, M07, M10 and M11, plus the M28 test-isolation finding in the addendum. All six remain supported at P1. This is a source and existing-evidence audit; no application code, live process or new test fixture was used by this auditor.

## M28 state-home addendum

[M28-F01](./M28.md#m28-f01--p1--test-isolation-inherited-state-home-can-overwrite-the-user-project-index) also warrants P1 for a separate test-isolation data-loss path. The normal [integration test script](../../package.json#L70) invokes Vitest, whose [configuration](../../vitest.config.ts#L1) does not clear `QUARTERDECK_STATE_HOME`. [withTemporaryHome](../../test/utilities/temp-dir.ts#L27) changes `HOME` and `USERPROFILE` only, while [getRuntimeHomePath](../../src/state/project-state-utils.ts#L23) prefers the inherited state-home override. In a test using that helper, [project-state.integration.test.ts](../../test/integration/project-state.integration.test.ts#L656) directly overwrites `getProjectsRootPath()/index.json` with deliberately malformed fixture data. If a developer runs the ordinary integration suite with `QUARTERDECK_STATE_HOME` pointing at their real state, this replaces their project index; no project-ID collision or spawned runtime is needed. The M28 reviewer's private synthetic override check confirmed the path escape, but the destructive test was not run against any real state directory. This is independent of the five application findings above.
