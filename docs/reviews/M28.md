# M28 — Test infrastructure and Agent Lab

Baseline: `fb9a34fbc41fb8464dd5133db066120c24eb866c`. The exact 263-file primary inventory is partitioned without overlap in [M28-coverage.json](M28-coverage.json): 62 Agent Lab/E2E/shared-infrastructure files, 91 integration/API/state tests, and 110 other runtime tests. This review follows test promises through helpers and production boundaries; a passing test count alone is not treated as coverage. The two disjoint supporting audits are [integration](M28-integration.md) and [runtime](M28-runtime.md).

### M28-F01 — P1 · Test isolation: inherited state home can overwrite the user project index

**Trigger and impact.** Run the root integration suite while `QUARTERDECK_STATE_HOME` points to a real Quarterdeck state directory. The `withTemporaryHome` helper changes `HOME` and `USERPROFILE` but leaves that override intact. The malformed-index integration case then writes `projects/index.json` under the inherited state root, replacing the user's project index with a deliberately invalid fixture. This is a direct persistent data write, not merely a false test result or an inferred server side effect.

**Evidence.** [`test/utilities/temp-dir.ts`](../../test/utilities/temp-dir.ts) lines 27–46 isolates only the two home variables. [`src/state/project-state-utils.ts`](../../src/state/project-state-utils.ts) lines 23–29 resolves the explicit state-home override first. [`test/integration/project-state.integration.test.ts`](../../test/integration/project-state.integration.test.ts) lines 656–679 unconditionally creates the projects directory and calls `writeFileSync` on `getProjectsRootPath()/index.json` inside `withTemporaryHome`; the fixture intentionally omits required `repoPath`. [`vitest.config.ts`](../../vitest.config.ts) and the root [`package.json`](../../package.json) test scripts do not clear the override. The shared spawned-server path has the same inheritance: [`test/utilities/git-env.ts`](../../test/utilities/git-env.ts) lines 6–16 copies it, and [`test/utilities/integration-server.ts`](../../test/utilities/integration-server.ts) lines 145–155 sets only `HOME`, `USERPROFILE`, and the port. A nonruntime check set the override to a disposable sentinel root; inside `withTemporaryHome`, both `getRuntimeHomePath()` and `createGitTestEnv().QUARTERDECK_STATE_HOME` still resolved to the sentinel rather than the temporary HOME. The sentinel was removed. The unsafe integration case was not executed.

**Remedy and validation.** Make the shared disposable-home helper set and restore an isolated `QUARTERDECK_STATE_HOME`, and make `startQuarterdeckServer` default its child state root from its disposable `homeDir` while preserving a caller's explicit synthetic override. Add a focused inherited-override regression using a sentinel external index: run the malformed-index case only against disposable paths and assert the sentinel remains unchanged. Keep test entrypoints isolated so helpers outside this pair cannot inherit real state.

### M28-F02 — P2 · Windows launcher: fake Agent Lab PowerShell shim names an unset script variable

**Trigger and impact.** Start the deterministic fake or fake-Claude Agent Lab on Windows, then launch an enabled task agent. The generated `.ps1` shim passes `QUARTERDECK_AGENT_LAB_FAKE_CODEX` as the script path, but the isolated environment defines `QUARTERDECK_AGENT_LAB_FAKE_AGENT`. The fake provider cannot start through the PowerShell launch path, so the Windows Lab cannot exercise its task-agent behavior.

**Evidence.** [`scripts/agent-lab/fixture.ts`](../../scripts/agent-lab/fixture.ts) lines 58–82 generate the shell and `.cmd` launchers with `FAKE_AGENT`, but the sibling `.ps1` at line 77 uses `FAKE_CODEX`. [`scripts/agent-lab/environment.ts`](../../scripts/agent-lab/environment.ts) lines 102–140 sets `FAKE_AGENT` and never `FAKE_CODEX`. [`src/core/windows-cmd-launch.ts`](../../src/core/windows-cmd-launch.ts) lines 53–58 and 160–183 select a sibling PowerShell shim for a resolved `.cmd` executable. A disposable, nonruntime launcher-generation check confirmed the `.cmd` contains the configured name while the `.ps1` contains only the unset name. [`test/utilities/agent-lab.test.ts`](../../test/utilities/agent-lab.test.ts) checks fake POSIX launcher content and executes real Codex's Windows shim, but has no fake Windows shim execution assertion.

**Remedy and validation.** Generate the fake `.ps1` from the same script-variable constant as the shell and `.cmd` launchers. Exercise an actual generated fake `.ps1` on native Windows with a disposable fake script and verify Codex, Pi, and fake Claude version/start arguments; retain the static cross-launcher contract check on other platforms.

### M28-F03 — P2 · Integration harness: startup timeout leaves the child server running

**Trigger and impact.** If a child server does not print its ready URL within ten seconds, `startQuarterdeckServer` rejects before returning the `stop` handle. It neither terminates nor awaits that child. Many integration callers allocate disposable directories and call the helper before entering their `try/finally`, so a slow startup can leave both an unowned Quarterdeck child and its fixtures behind. Later tests can then encounter a conflicting runtime or port.

**Evidence.** [`test/utilities/integration-server.ts`](../../test/utilities/integration-server.ts) lines 43–61 reject the startup wait on timeout; lines 145–171 spawn the child and await the wait directly, with teardown available only in the returned object at lines 172–214. [`test/integration/project-discovery.integration.test.ts`](../../test/integration/project-discovery.integration.test.ts) lines 20–33 calls the helper before its cleanup `finally`, as does [`test/integration/state-streaming.integration.test.ts`](../../test/integration/state-streaming.integration.test.ts) lines 86–107. [`test/utilities/integration-server.test.ts`](../../test/utilities/integration-server.test.ts) lines 39–143 tests teardown after a successful startup, not failure before handle return. This is a source-backed failure path; no runtime was launched to force a timeout for this review.

**Remedy and validation.** Own child cleanup inside `startQuarterdeckServer` from the instant `spawn` succeeds: on startup rejection, terminate its process tree, await close, and preserve the startup error with cleanup failure context. Test timeout, early exit, and spawn error with controlled child processes, asserting no child or temporary root survives.

### M28-F04 — P2 · Windows smoke: fixture expects ignored-path junctions the worktree setup no longer creates

**Trigger and impact.** Run the required native Windows smoke test through successful task-worktree creation. The fixture writes ignored `.windows-smoke-cache` and `.windows-smoke.env` paths but no `.worktreeinclude`; the test then calls `lstatSync` on a purported mirrored directory and requires a symbolic link. Current setup copies only explicitly included regular files and never creates the old ignored-directory junction. The gate fails at this assertion before its later PTY and ownership checks, so a green Windows smoke result is unattainable on the current contract.

**Evidence.** [`test/integration/windows-native-smoke.integration.test.ts`](../../test/integration/windows-native-smoke.integration.test.ts) lines 571–580 creates `.gitignore` and ignored fixture paths, but no include file; lines 776–794 require the directory to be a symbolic link and the file to appear in the worktree. [`src/workdir/task-worktree-setup.ts`](../../src/workdir/task-worktree-setup.ts) line 143 invokes [`copyIncludedIgnoredPathsIntoWorktree`](../../src/workdir/task-worktree-symlinks.ts), which returns immediately without `.worktreeinclude` at lines 231–235 and otherwise copies regular files at lines 241–265. [`.github/workflows/test.yml`](../../.github/workflows/test.yml) lines 105–111 includes the native suite in the Windows job. The integration reviewer exercised that copy boundary in a disposable Git fixture: without an include file neither path appeared; with one, the directory appeared as an ordinary directory containing a copied file, not a link. This review did not execute the native Windows gate.

**Remedy and validation.** Update the smoke fixture to declare the intended ignored files in `.worktreeinclude` and assert independent regular-file copies and their contents; reserve a separate junction-specific test for behavior still supported by the implementation. Run the native Windows smoke gate and verify it reaches its later agent/PTY checks.

### M28-F05 — P3 · Test cleanup: host-simulation fixtures survive successful tests

**Trigger and impact.** Running the host-simulation unit suite creates three separate temporary fixture roots and never removes them. Repeated local or CI runs accumulate simulation configs and event ledgers in the system temp directory, weakening the disposable-fixture contract.

**Evidence.** [`test/runtime/runtime-host-simulation.test.ts`](../../test/runtime/runtime-host-simulation.test.ts) lines 11–25 create the roots; tests at lines 29, 87 and 101 call that helper, with no cleanup hook or `finally` in the suite. The runtime reviewer ran only this focused six-test suite under a private `TMPDIR`: all six tests passed, and fixture JSON files still existed afterward. The entire private temp root was then removed.

**Remedy and validation.** Use the shared `createTempDir` cleanup handle or an `afterEach`/`finally` that removes each fixture. Rerun the focused suite with a private temp root and assert it is empty at completion.

### M28-F06 — P3 · Regression test: per-entry reconciliation error case never injects an error

**Trigger and impact.** The test named “error in one entry does not prevent checking others” passes with two ordinary successful repairs and no thrown error. It therefore does not protect the production per-entry catch: a regression that aborts the sweep on one entry can still leave this test green.

**Evidence.** [`test/runtime/terminal/session-manager-reconciliation.test.ts`](../../test/runtime/terminal/session-manager-reconciliation.test.ts) lines 796–819 set up two stale permission badges with nonthrowing `vi.fn` callbacks, advance the timer, and assert both cleared; no mock or store call fails. [`src/terminal/session-reconciliation-sweep.ts`](../../src/terminal/session-reconciliation-sweep.ts) lines 33–62 is the per-entry error boundary the title claims to cover. This is a test-contract gap, not a demonstrated production failure.

**Remedy and validation.** Inject one controlled failure in the first entry's reconciliation seam, then assert the second entry is still checked/repaired and the first failure is surfaced or logged as intended. Keep the existing two-success case under a matching name if useful.

### M28-F07 — P3 · WebSocket test helper: “quiet” assertion ignores messages already queued

**Trigger and impact.** A WebSocket message can enter the test queue before `expectNoQueuedMessage` installs its listener. The helper then waits for future events and resolves even though an unexpected message remains queued. Three restore/buffering tests using it can miss an early duplicate or gap-violating message.

**Evidence.** [`test/runtime/terminal/ws-server.test.ts`](../../test/runtime/terminal/ws-server.test.ts) lines 183–195 implement the negative assertion solely with a future `message` listener; call sites at lines 393, 417 and 453 rely on it. The runtime reviewer evaluated the extracted real helper with a queue containing one synthetic Buffer; it resolved successfully and left queue length one. The positive `waitForIoMessage` helper at lines 158–174 does inspect the existing queue first.

**Remedy and validation.** Check the queue before listening and again when the quiet interval ends; add a helper regression with a prequeued message and one that arrives during the interval. Keep restore assertions on the wire order they intend to prove.
