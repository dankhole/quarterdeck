## Local editor recovery

Desktop file drafts have bounded recovery copies in `app://quarterdeck` storage inside the persistent Electron userData profile selected for the canonical runtime state home. Browser clients do not use this recovery store. Copies contain file text and its original revision, remain local, and never enter diagnostics. They are not encrypted independently of the user's disk/profile protections. The persistence correction uses explicitly strict IndexedDB transactions and acknowledges only transaction completion; its integrated source review and final packaged renderer/main-process-loss checks passed. An existing record, including an empty one, takes precedence over legacy local storage. A missing record permits one import, with legacy removal only after acknowledgement.

The limits are 32 drafts, 512 KiB per serialized draft and 2 MiB total, counting conservative UTF-16 storage bytes including original text and metadata. Previously recovered copies expire after 30 days; startup reports the expired count. Current unsaved text is never truncated or evicted to meet a quota. Failed writes retain the previous recovery bytes and current in-memory text. The new final native-action seal rejects loading, uncommitted revisions, and storage errors, even when the current draft count is zero. Export protects the text but does not repair storage or clear that veto. An unreadable or invalid existing snapshot quarantines new recovery writes until successful recovery or explicit reset. Confirmed Reset saved recovery may discard the unread snapshot only after all current drafts fit and their replacement transaction commits.

Startup offers the draft review dialog. Restore changes only a matching Files workspace after checking project, task creation time, repository/worktree path and file path; it refuses a newer unsaved tab. Restored text bypasses autosave until an explicit Save, which retains the original content-hash conflict check. Save draft/export and explicit discard remain available without writing the original file. Task/settings prompt contents are not persisted by this mechanism.
